# V5 Detail-Page Observatory Grammar

## Intent

Detailed pages should feel like views into the same Engineering Observatory rather than separate templates.

## Shared reading grammar

- **Project record:** Problem → Architecture → Development over time → Proof → Connected knowledge → Engineering record
- **Field note:** Context → Decision → Evidence → Lessons → Source system
- **Documentation:** Context → Procedure → Operations → Verification → Project trace
- **Talk record:** Context → Practice → Lessons → Shared evidence
- **About:** Roles → Public work → Recognition → Research → Operating principles → Continue through the observatory
- **Story:** Engineering evolution across Framework → DevOps → Cloud Native → Platform → OSS → AI-assisted Engineering

## Visual rules

1. Prefer editorial hierarchy, dividers, timelines and diagrams over repeated cards.
2. Architecture and development-over-time signals are primary media.
3. Claims should sit close to proof or a path to proof.
4. Knowledge keeps provenance to a system, decision, incident or practice.
5. Mobile layouts preserve meaning without hover and use vertical reading flows.
6. Development activity gracefully falls back when metadata is unavailable.

## Development Observatory

The project source view should communicate ongoing engineering, not repository popularity. Primary signals are first commit, cumulative commits, releases, latest release, last push, active duration and recent activity. Stars/forks/issues remain secondary context.
